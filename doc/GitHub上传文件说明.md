# GitHub 上传文件说明

## 一、总原则

仓库只放**工具运行必需的文件**。所有内部文档、备份、研究资料一律留在本地 `doc/`，不上传。

原因：本仓库为**公开仓库**，任何人都能看到并下载全部内容。上传内部文档会泄露防另存的实现机制，上传备份等于把可直接使用的完整工具送给别人——两者都会让"另存不可用"的设计失去意义。

## 二、必须上传（共 4 个文件，约 33 KB）

```
仓库根目录/
├── index.html                    6 KB   页面壳（介绍文字 + DOM 骨架）
└── assets/                              目录名与位置都不能改
    ├── style-a1b2c3.css          5 KB   样式
    ├── app-a1b2c3.js            25 KB   主程序
    └── core-a1b2c3.js           2.8 KB  核心 SVG 生成模块
```

这四个文件缺一不可。少任何一个是**界面能开但生成 SVG 失效**。

**关键约束**：主程序用绝对路径 `/assets/core-a1b2c3.js` 加载核心模块，所以：

- `assets/` 必须位于站点根目录，不能改名、不能嵌套到子目录；
- 若启用 GitHub Pages，仓库名须为 `用户名.github.io`，或绑定自定义域名；
- 用普通仓库名（如 `pic2svg`）开启 Pages 时，地址是 `https://用户名.github.io/pic2svg/`，`/assets/core...` 会指向 `https://用户名.github.io/assets/` 而 404，工具不可用。

## 三、不得上传

| 文件/目录 | 不上传的原因 |
|---|---|
| `doc/index.html.bak-20261126-1108` | 改造前的**完整单文件版**，双击即用、另存也完整。上传等于直接公开可下载的原版工具，彻底抵消防另存设计。 |
| `doc/改造方案-另存不可用.md` | 写明核心机制（绝对路径加载、module 阻断原理）与测试方法，公开后他人可据此轻松绕过防护。 |
| `doc/上线改进清单.md` | 内部待办与风险评估，属开发资料。 |
| `doc/使用说明.md` | 含本地启动方式与恢复旧版命令，属内部操作资料。 |
| `.workbuddy/` | 项目元数据与工作日志，非工具内容。 |

## 四、建议添加 `.gitignore`

在仓库根目录新建 `.gitignore`，内容如下，可防止误传：

```
doc/
.workbuddy/
*.bak-*
*.log
.DS_Store
```

## 五、若需要 README

可以另写一个**简短的公开版 `README.md`**，只包含：工具用途、在线地址、使用方法（选图 → 取点 → 生成/下载）、浏览器要求。不要把 `doc/` 里的内部文档直接改名当 README。

## 六、上传后验证

1. 通过 HTTP 方式打开线上地址，确认工具界面出现；
2. 取点并生成一次 SVG，确认成功；
3. 浏览器开发者工具 Network 面板确认 `assets/core-a1b2c3.js` 返回 200；
4. 再试一次"另存为 → 网页，仅 HTML"，打开后应只剩介绍文字、无工具界面——若如此，说明防护生效。

## 七、必须接受的事实

公开仓库意味着**源码完全开放**：任何人下载全部 4 个文件后，自己起本地 HTTP 服务即可获得完整功能。本项目的防另存设计只能挡住"顺手保存网页"，挡不住主动获取源码。若要真正保护权益，只能靠许可协议（LICENSE）、版权声明和署名要求等非技术手段。
